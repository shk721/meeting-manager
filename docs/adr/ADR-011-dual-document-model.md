# ADR-011 — Dual Document Model

| الحقل | القيمة |
|---|---|
| **الحالة** | Accepted |
| **التاريخ** | 2026-07-09 |
| **المحور** | Architecture |
| **يعتمد على** | ADR-010 |

---

## السياق

الوثائق التي يحتاجها المستخدمون تنقسم إلى نوعين متمايزين في طبيعتهما:
- تصدير سريع غير رسمي (مثل تنزيل قائمة مهام بصيغة Excel)
- وثيقة رسمية تستوجب الأرشفة والاعتماد والتدقيق

النموذج الموحّد لكليهما يُعقّد أحدهما أو يُضعف الآخر.

## القرار

يعتمد النظام نموذجَين مستقلَّين للوثائق:

### Ephemeral Document (وثيقة مؤقتة)
- توليد فوري وتدفق مباشر إلى المستخدم
- لا يُحفظ في قاعدة البيانات
- لا يحمل ID مستقلاً
- مناسب: تنزيل سريع، مشاركة فورية، معاينة
- مثال: "تنزيل قائمة المهام CSV"

### Persisted Document (وثيقة محفوظة)
- يُخزَّن في `generated_documents` مع snapshot مجمّد للبيانات
- يحمل ID مستقلاً ودورة حياة كاملة
- قابل للإصدارات والاعتماد والتوزيع
- مناسب: محاضر اجتماعات، تقارير خطط، وثائق حوكمة
- مثال: "محضر اجتماع مجلس الإدارة — نسخة معتمدة"

## المبررات

- الوثيقة الرسمية تستوجب نزاهة بيانات (Frozen Snapshot — انظر ADR-016)
- التصدير السريع لا يستحق تكلفة التخزين والإدارة
- المستخدم يختار صراحةً: "تنزيل" أو "حفظ في الأرشيف"

## النتائج

- ✅ مرونة: السرعة عند الحاجة، الرسمية عند الضرورة
- ✅ لا تُثقَّل قاعدة البيانات بكل عملية تصدير
- ✅ مسار تدقيق واضح للوثائق الرسمية فقط
- ⚠️ واجهة المستخدم تحتاج تمييزاً واضحاً بين المسارين
