# ADR-014 — RTL First

| الحقل | القيمة |
|---|---|
| **الحالة** | Accepted |
| **التاريخ** | 2026-07-09 |
| **المحور** | Product Evolution |
| **يسري على** | جميع مكونات Document Engine |

---

## السياق

المنصة موجّهة للبيئة المؤسسية العربية. العربية هي اللغة الأساسية للمستخدمين والوثائق. الكثير من أنظمة المصادر المفتوحة تعامل RTL كـ "إضافة" أو `option`، ما يُفضي إلى أخطاء في التنسيق تظهر فقط عند الاستخدام الفعلي.

## القرار

**العربية والـ RTL هما الوضع الافتراضي في جميع مكونات Document Engine.**
أي دعم للغات LTR يُعدّ امتداداً لاحقاً، وليس العكس.

### المتطلبات الملزمة لكل مكوّن

| المتطلب | التفاصيل |
|---|---|
| `dir="rtl"` | افتراضي في كل HTML/PDF template |
| الخطوط العربية | Tajawal أو Cairo (Google Fonts، مُضمَّنة في Renderer) |
| التواريخ | صيغة `يوم شهر سنة` (هجري أو ميلادي حسب إعدادات المؤسسة) |
| الأرقام | الأرقام العربية-الهندية اختيارية (يُضبط من Document Theme) |
| التخطيط | المحتوى يبدأ من اليمين؛ الهوامش والمسافات تُحسب RTL |
| الجداول | رؤوس الأعمدة RTL؛ محاذاة النص لليمين افتراضياً |

### محرّك الـ PDF

يُستخدم **Puppeteer** (HTML→PDF) لا pdfkit، لأن CSS يُطبّق RTL بشكل صحيح تلقائياً عبر `direction: rtl`.

### Document Theme

`DocumentTheme` يحتوي على:
```typescript
rtlEnabled: boolean;  // default: true
fontFamily: string;   // default: 'Tajawal, Arial'
```

## المبررات

- التصميم RTL-first يُلغي أخطاء التنسيق التي تظهر لاحقاً
- الخطوط العربية تُضمَّن في الـ Renderer مرة واحدة، لا تتكرر في كل قالب
- Puppeteer + CSS = دعم RTL كامل بلا جهد إضافي

## النتائج

- ✅ جميع الوثائق تبدو احترافية بالعربية من اليوم الأول
- ✅ دعم الإنجليزية لاحقاً لا يكسر أي شيء (يُضاف `rtlEnabled: false` فقط)
- ⚠️ يستوجب التحقق من كل Renderer بوثيقة عربية فعلية قبل اعتماده
