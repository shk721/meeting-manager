# ADR-016 — Frozen Document Principle

| الحقل | القيمة |
|---|---|
| **الحالة** | Accepted |
| **التاريخ** | 2026-07-09 |
| **المحور** | Architecture / Compliance |
| **يعتمد على** | ADR-011 (Persisted Documents) |

---

## السياق

الوثيقة الرسمية تُنشأ في لحظة زمنية محددة وتعكس حالة البيانات في تلك اللحظة. بعد إنشائها:
- قد تتغير بيانات الخطة (تقدّم الأنشطة)
- قد تُضاف قرارات جديدة للاجتماع
- قد يتغير تشكيل اللجنة

إذا تحدّثت الوثيقة تلقائياً، فإنها تفقد قيمتها كـ "وثيقة رسمية في وقت محدد".

## القرار

**أي Persisted Document (ADR-011) يُعدّ Snapshot ثابتة وقت التوليد.**

### التطبيق

```typescript
// عند الحفظ في generated_documents
{
  entityType: "plan",
  entityId: 7,
  frozenData: {           // snapshot مجمّد — لا يتغير
    plan: { title: "خطة التحول", progress: 67, ... },
    phases: [...],
    decisions: [...]
  },
  fileUrl: "...",
  generatedAt: "2026-07-09T10:30:00Z",
  version: 1
}
```

### تحديث البيانات بعد التوليد

| الحالة | السلوك |
|---|---|
| تغيّرت بيانات المصدر | تظهر أيقونة `⚠ تحديثات متاحة` على الوثيقة |
| المستخدم أراد تحديث الوثيقة | يُنشئ نسخة جديدة `version: 2` بـ frozenData جديد |
| النسخة القديمة | تبقى محفوظة ومتاحة في سجل الإصدارات |

### اللحظة التي يسمح بالبيانات الحية (Live Data)

**معاينة الـ Wizard فقط**: أثناء خطوة "Generate" قبل الحفظ، تُعرَض المعاينة ببيانات حية. لحظة "الحفظ في الأرشيف" هي لحظة التجميد.

## المبررات

- **متطلب قانوني**: الوثيقة الرسمية المعتمدة يجب أن تعكس ما كان صحيحاً وقت اعتمادها
- **مسار تدقيق**: "كانت الخطة 67% حين أُرسل التقرير لمجلس الإدارة"
- **نزاهة الأرشيف**: لا يمكن إعادة تأريخ الوثيقة بإدخال بيانات أحدث

## النتائج

- ✅ مسار تدقيق كامل وموثوق
- ✅ لا يمكن "تحسين" وثيقة قديمة بأثر رجعي
- ✅ الوثيقة الرسمية صالحة قانونياً
- ⚠️ `frozenData jsonb` قد يكون ضخماً — يُضغَّط أو يُخزَّن خارج DB للوثائق الكبيرة (Phase 2)
