# ADR-018 — Context-Driven Document Generation

| الحقل | القيمة |
|---|---|
| **الحالة** | Accepted |
| **التاريخ** | 2026-07-09 |
| **المحور** | Architecture |
| **يعتمد على** | ADR-010، ADR-017 |

---

## السياق

في غياب سياق محدد، الوثيقة تُصبح "تقرير عام" لا يُمكن أرشفته، تصفيته، أو ربط صلاحياته بالكيانات الصحيحة. كما يصعب على النظام اقتراح القوالب المناسبة دون معرفة سياق الطلب.

## القرار

**كل وثيقة يجب أن ترتبط بسياق (Context) محدد وصريح.**

### السياقات المدعومة (Contexts)

| السياق | entityType | مثال |
|---|---|---|
| اجتماع | `meeting` | محضر اجتماع رقم 42 |
| خطة | `plan` | تقرير حالة خطة التحول |
| سياق حوكمة | `governance` | تقرير لجنة التخطيط الاستراتيجي |
| قرار | `decision` | موجز القرار رقم 15 |
| برنامج / مشروع | `dt_project` | تقرير محركات التحول الرقمي |
| مستخدم | `user` | تقرير إنتاجية الموظف |
| مؤسسة / قسم | `organization` | التقرير السنوي للمؤسسة |

### التطبيق في API

```
POST /documents/generate
{
  "entityType": "meeting",     // السياق — إلزامي
  "entityId": 42,              // الكيان — إلزامي
  "templateId": "meeting-minutes",
  "format": "pdf"
}
```

لا يُقبل طلب توليد بدون `entityType` + `entityId`.

### الاستثناء الوحيد المسموح به

وثائق تقارير مؤسسية شاملة (مثل "التقرير السنوي") ترتبط بـ `entityType: "organization"` + `entityId: orgId`. لا يوجد "وثيقة حرة" حقيقية.

### التأثير على UX

- **من صفحة الكيان**: السياق مُعبَّأ تلقائياً (pre-filled) — المستخدم يختار القالب والصيغة فقط
- **من مركز الوثائق**: المستخدم يختار السياق أولاً، ثم تُفلتر القوالب لتُظهر المناسب له فقط

### التأثير على البحث والفلترة

```
GET /documents?entityType=meeting&entityId=42   — جميع وثائق هذا الاجتماع
GET /documents?entityType=plan&status=approved   — تقارير الخطط المعتمدة
GET /documents?entityType=governance             — جميع وثائق الحوكمة
```

## المبررات

- **البحث**: السياق = metadata أساسي للفلترة والأرشفة
- **الصلاحيات**: من يملك صلاحية رؤية الاجتماع يملك صلاحية رؤية وثائقه (يُطبَّق تلقائياً)
- **القوالب**: النظام يقترح فقط القوالب المناسبة للسياق (لا قائمة إرباك كاملة)
- **Intelligence Engine**: الذكاء الاصطناعي يحتاج سياقاً واضحاً لتوليد تحليلات ذات معنى

## النتائج

- ✅ كل وثيقة في الأرشيف يمكن ربطها بكيانها المصدر
- ✅ الصلاحيات تُكتسب من الكيان الأصل (لا إعادة تعريف)
- ✅ القوالب المقترحة دائماً وثيقة الصلة بالسياق
- ✅ التقارير الشاملة ممكنة عبر `entityType: "organization"`
- ⚠️ لا يُسمح بوثائق "حرة" — أي طلب توليد بدون سياق يُرفض بـ `400 Bad Request`
